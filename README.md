# Photo Booth Receipt Web App — Google Apps Script

A complete, working photobooth + receipt + payment system built entirely
on Google Apps Script, Google Sheets, and Google Drive.

---

## STEP 1 — System Architecture

- **Frontend** (`Index.html`, `Styles.html`, `Scripts.html`, `Receipt.html`,
  `Settings.html`) is a single-page app served by `doGet()`. It manages the
  whole workflow client-side: camera access, countdown timer, capture,
  filters, thumbnails, canvas-based photo-strip generation, checkout form,
  and the printable receipt.
- **Backend** (`Code.gs`, `Config.gs`, `Database.gs`, `Drive.gs`,
  `Settings.gs`, `Transactions.gs`, `Utils.gs`) receives the finished photos
  as base64 from the browser via `google.script.run`, saves everything to
  Drive and Sheets, generates QR codes, and returns receipt data.
- **QR codes** are generated by requesting an image from the public
  QR Server image API (`api.qrserver.com`) — no external library needed,
  it's just an `<img src="...">`. The photo QR points at a real, viewable
  Google Drive image URL (see Step 3), not just the transaction ID.
- **Data storage**: Google Sheets (`Transactions`, `Settings`, `Counters`)
  and Google Drive (`PhotoBooth/Original Photos`, `Photo Strips`, `Receipts`).

## STEP 2 — Google Sheet Setup

`setupPhotobooth()` creates a new spreadsheet called **"PhotoBooth Database"**
(or reuses one already recorded in Script Properties) with three sheets:

- **Transactions** — one row per completed sale, headers:
  `Transaction ID, Date, Time, Customer Name, Photo Label, Package,
  Quantity, Price, Discount, Total, Payment Method, Original Photo IDs,
  Original Photo URLs, Photo Strip File ID, Photo Strip URL, Photo QR URL,
  Payment QR Data, Status, Created By`
- **Settings** — a simple `Key | Value` table, pre-filled with defaults from
  `Config.gs`, editable from the in-app ⚙️ Settings panel.
- **Counters** — internal, tracks the last transaction number issued per day
  so numbers like `PB-20260905-0001` never duplicate, even under concurrent
  saves (protected with `LockService`).

Headers are only written if missing/mismatched, so re-running setup is safe.

## STEP 3 — Google Drive Setup

`setupPhotobooth()` also creates this folder structure in the account's
My Drive (or reuses a folder named "PhotoBooth" if one already exists):

```
PhotoBooth/
├── Original Photos/     ← every captured/uploaded photo, saved individually
├── Photo Strips/        ← the generated strip image per transaction
└── Receipts/            (reserved — see PDF note below)
```

Example filenames for transaction `PB-20260905-0001`:
```
PB-20260905-0001-Original-01.jpg
PB-20260905-0001-Original-02.jpg
PB-20260905-0001-Original-03.jpg
PB-20260905-0001-Original-04.jpg
PB-20260905-0001-PhotoStrip.png
```

**Drive sharing / QR access note (important):** Apps Script can't serve
arbitrary files at a clean custom URL the way a normal web server can. The
safest practical approach used here: each saved file's sharing is set to
"Anyone with the link – Viewer," and the QR code points at
`https://drive.google.com/uc?export=view&id=FILE_ID`, which renders the
image directly in the browser instead of Drive's preview page — so
scanning the code actually shows the photo. If your Google Workspace
domain restricts external link sharing, the files still save correctly;
only the public link will be limited to people inside your organization.
That's a Workspace admin policy, not a bug in the app.

**Receipt PDF note:** Apps Script does not have a native PDF-generation API
outside of converting a Google Doc/Sheet to PDF, which is impractical for a
per-transaction custom-styled receipt. This app instead ships a print-ready
HTML/CSS receipt (`Receipt.html`) with `@media print` rules tuned for 58mm
and 80mm thermal printers as well as A4 — the cashier prints it directly
from the browser's print dialog, which is the standard approach for
real thermal-printer POS/receipt systems. The `Receipts/` Drive folder is
created and ready if you later want to wire up PDF export.

## STEP 4 — Complete Apps Script Code

All files are attached below (also included as downloadable files):

- `Code.gs` — web app entry point (`doGet`, `include`)
- `Config.gs` — constants, Script Properties helpers, default settings
- `Database.gs` — Sheets creation, headers, transaction number counter
- `Drive.gs` — Drive folder structure, file save/share helpers
- `Utils.gs` — date/QR/sanitization helpers
- `Settings.gs` — `getSettings()` / `saveSettings()`
- `Transactions.gs` — `setupPhotobooth()` and `saveTransaction()`
- `Index.html` — app shell, all screens
- `Styles.html` — pink/white theme, responsive + print CSS
- `Scripts.html` — full frontend logic (camera, timer, capture, strip, save)
- `Receipt.html` — receipt markup template
- `Settings.html` — admin settings modal

Every `google.script.run.xxx(...)` call in `Scripts.html` (`getSettings`,
`saveSettings`, `saveTransaction`) has a matching server-side function with
the exact same name, defined exactly once.

## STEP 5 — Installation

1. Go to [script.google.com](https://script.google.com) → **New project**.
2. Rename the project (e.g. "Photo Booth Receipt App").
3. Delete the default empty `Code.gs` content, or just overwrite it.
4. For each `.gs` file listed above: click **+ → Script**, name it exactly
   (e.g. `Config`), and paste the matching code.
5. For each `.html` file: click **+ → HTML**, name it exactly (e.g. `Index`,
   `Styles`, `Scripts`, `Receipt`, `Settings` — no `.html` extension needed
   in the Apps Script editor, it's added automatically), and paste the code.
6. Save the project (Ctrl/Cmd+S).

## STEP 6 — Run Setup

1. In the Apps Script editor, select the `Transactions.gs` file.
2. In the function dropdown at the top, choose **setupPhotobooth**.
3. Click **Run**.
4. The first time, Google will ask you to authorize the script (Sheets,
   Drive, and script properties access) — click **Review permissions**,
   choose your account, click **Advanced → Go to [project name] (unsafe)**,
   then **Allow**. This warning is normal for your own unpublished scripts.
5. Check **View → Logs** (or **Executions**) to confirm it printed
   "SETUP COMPLETE." along with links to the new spreadsheet and folders.

## STEP 7 — Deployment

1. Click **Deploy → New deployment**.
2. Click the gear icon next to "Select type" → choose **Web app**.
3. Description: anything you like.
4. **Execute as:** Me (your account) — this is required so the app can
   write to your Sheets/Drive on behalf of anyone using the booth.
5. **Who has access:** choose based on your use case —
   - "Anyone" if the booth will be used by guests without a Google login.
   - "Anyone within [your organization]" for internal/Workspace use only.
6. Click **Deploy**, then **Authorize access** again if prompted.
7. Copy the **Web app URL** — this is what you open on the photobooth
   touchscreen computer (or any tablet/laptop/phone).
8. Every time you edit the code, create a **new deployment version**
   (or use "Manage deployments → Edit → new version") for changes to
   go live at the same URL.

## STEP 8 — Configuration

Everything below is editable from the ⚙️ **Settings** button in the app —
no code editing required:

- **Business:** name, address, phone, email, logo URL, thank-you message
- **Photo Strip:** default label ("Photo Booth by Aki"), number of photos,
  width/height/spacing, background color, font, font size, bold, alignment,
  show date, show transaction number
- **Payment:** provider (e.g. "GCash"), account/name, a payment URL/text
  (auto-generates a QR), OR a fixed payment QR image URL if you'd rather
  upload/host your own QR image
- **Receipt:** currency symbol (defaults to ₱), receipt width (58mm / 80mm /
  A4), footer text, default package name, default price

Changes save immediately to the **Settings** sheet and apply the next time
the app loads settings (on page load, or you can just reload the web app
tab after saving).
